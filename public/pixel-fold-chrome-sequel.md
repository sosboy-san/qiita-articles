## 第2章：大画面なら文字も大きい。そう思っていた時期が私にもありました。

大画面で動画を見たい。電子書籍を読みたい。複数のアプリを並べて使いたい。

もちろん、そういう人も多いだろう。

しかし、一定数はいると思うのだ。

**「画面が大きければ、Webサイトの文字も大きくなって読みやすいのでは？」**

そう期待して折りたたみスマートフォンを買った人が。

特に、そろそろ目が怪しくなってきた世代である。

昔は小さな文字でも平気だった。

解像度が上がれば喜んでいた。

ところが今は違う。

高解像度の画面を見ながら、文字を拡大している。

ディスプレイは進化した。

CPUも進化した。

通信速度も進化した。

<font color="#c44e58"><strong>私の目だけが、順調に性能を落としている。</strong></font>

しかも、どうやらアップデートの予定はない。

そんな人間にとって、Pixel Foldの大画面は魅力的である。

ところが。

ここには、とんでもない罠がある。

<font color="#c44e58"><strong>折りたたみスマホの方が、普通のスマホより文字が小さくなることがあるのだ。</strong></font>

画面は大きい。

なのに文字は小さい。

何を言っているのかわからないかもしれないが、私も最初は何をされたのかわからなかった。

もはや習慣である。

そして、この二つのサイトが、今回の問題をわかりやすくしてくれる。

横に情報が並ぶ。

そして、肝心の文字が小さい。

当然OFFにしている。

しかし、それでも期待する表示にならない。

いや、だからPC版サイトはOFFにしているんだが。

どうやら、こちらの希望は通じないらしい。

### 「PC版サイトOFF」は、モバイル表示の確約ではない

ここで少し技術的な話をする。

Chromeの「PC版サイト」をOFFにすることと、Webサイトが必ずモバイル向けレイアウトを表示することは、同じではない。

サイト側では、User-Agentなどのブラウザ情報や、CSSで参照する表示領域の幅などによって、表示を変えることがある。

折りたたみスマートフォンは、このあたりが少々厄介だ。

Androidスマートフォンなのに、内側画面は広い。

ただし、Yahoo!やImpressが具体的に何を使って判定しているかまでは、今回特定していない。

確認できているのは、**私の環境ではChromeの設定だけでは解決せず、User-Agentを指定するとYahoo!などを目的のモバイル向け表示にできた**、ということだ。

画面が大きいことと、文字が読みやすいことは、別問題なのである。

アドレスバーがある。

その上にはタブバーがある。

ようやく記事が始まったと思ったら、表示できる本文は思ったほど多くない。

<font color="#c44e58"><strong>Googleさん、これ、本気でタッチして選ばせるつもりですか。</strong></font>

少なくとも私の使い方では、上部のタブバーは表示量の邪魔でしかない。タブを使いたくないのではなく、常時そこに並べておいてほしくないのである。

### Chromebookでは、普通にできているのに

さらに腑に落ちないのが、Chromebookである。

私が使ったChromebookでは、タブレットモードにすると横一列のタブが消える。

指で使う状態になったら、表示もそれに合わせて変わる。

とても普通だ。

**普通すぎて、なぜFoldではそうならないのか、余計に気になる。**

私が使っているAndroidの大画面Chromeでは、Foldでもタブレットでも、この横並びタブが出てくる。

同じGoogleのChromeなのに、片方では指で使うことに合わせてくれる。もう片方では、小さなタブが横にぎっしり並ぶ。

Googleさん、この使い分けについて、ちょっと詳しくお話を伺いたい。

できれば担当の方にも、この状態でタブをたくさん開き、指だけで目的のタブを選んでいただきたい。

マウスは一度、机に置いてからお願いします。

※ここでの比較は、私が使った環境での体験である。すべてのAndroidブラウザや、すべてのChromebookの表示を一括りにしているわけではない。

そんなわけで、今回の課題は二つある。

**サイト側には、読みやすいモバイル向け表示をしてほしい。**

**Chrome側には、限られた画面を本文に使わせてほしい。**

どちらも、大画面をちゃんと大画面として使うための話である。

## 第6章：文字も、表示領域も、取り戻す

今回のスクリプトの仕事は、大きく二つある。

- User-Agentを指定し、モバイル向け表示を狙う。
- 内側画面でChrome上部のタブバーを非表示にする。

文字サイズそのものを直接変更するスクリプトではない。

モバイル向けのレイアウトで読みやすくし、タブバーに取られていた領域を本文へ返す。

片方だけでは、私にとっては半分の解決だ。

### まずは実行の準備

Termuxから、Shizuku経由のrishでシェルコマンドを実行できる状態にしておく。

以下は、rishを `~/rish` に配置した環境の例である。単にTermuxへ貼り付けるだけでは動かない。

今回の検証では、Chromeをデバッグアプリに指定した。

```bash
~/rish -c 'am set-debug-app --persistent com.android.chrome'
```

指定内容は次のコマンドで確認できる。

```bash
~/rish -c 'settings get global debug_app'
```

私の環境では `com.android.chrome` が返る状態で動作した。

`chrome://flags/#enable-command-line-on-non-rooted-devices` は **Default** のままである。

これは、今回のデバッグアプリ指定と組み合わせた実測条件だ。一般的なChromiumの案内には非root向けフラグを有効にする方法もあるが、ここでは手順を混ぜず、確認できた条件を記載している。

### 完成したスクリプト

`chrome-notabs-mobile.sh` として保存する。

以下は検証時に成功したスクリプトそのままである。

```bash
#!/data/data/com.termux/files/usr/bin/bash
~/rish -c 'am force-stop com.android.chrome'
~/rish -c 'echo '\''chrome --enable-test-intents --tab-strip-height-transition-threshold=2000 --user-agent="Mozilla/5.0 (Linux; Android 17; Pixel 10 Pro Fold) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/155.0.0.0 Mobile Safari/537.36"'\'' > /data/local/tmp/chrome-command-line'
~/rish -c 'cmd device_state state 0'
~/rish -c 'am start -W -n com.android.chrome/com.google.android.apps.chrome.Main'
~/rish -c 'cmd device_state state reset'
```

保存したディレクトリで、次のように実行する。

```bash
bash chrome-notabs-mobile.sh
```

Chromeをいったん強制終了するので、入力中のフォームなどは先に保存しておく。

短いスクリプトである。

ただし、この短さにたどり着くまでが長かった。

### ① Chromeを止めて、起動オプションを書く

```bash
~/rish -c 'am force-stop com.android.chrome'
```

まずChromeを止める。起動済みのChromeに設定ファイルを書くだけでは、起動時の読み込みをやり直せないためだ。

続く長い `echo` は、`/data/local/tmp/chrome-command-line` に起動オプションを書き込んでいる。

途中の ` '\'' ` は引用符を受け渡すためのシェル記法で、飾りではない。見た目を整えようとして消すと、別の戦いが始まる。

この行はファイルを上書きするため、すでに別の起動オプションを設定している場合は、先に内容を控えておく。

### ② User-Agentを指定する

起動オプションから、この部分を取り出す。

```text
--user-agent="Mozilla/5.0 (Linux; Android 17; Pixel 10 Pro Fold) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/155.0.0.0 Mobile Safari/537.36"
```

User-Agentは、ブラウザがサイトへ伝える識別情報のひとつだ。

ここでは `Mobile` を含む文字列を指定し、モバイル向けの表示を狙っている。

ただし、これで端末の幅が変わるわけでも、すべての識別情報が一括で変わるわけでもない。サイトが画面幅やUser-Agent Client Hintsなどを参照していれば、期待どおりにならないこともある。

**全サイト対応の魔法ではなく、自分が読むサイトで効果を確認した調整である。**

また、`Chrome/155.0.0.0` は固定値だ。Chromeを更新しても、この文字列は自動更新されない。

### ③ タブバーの切り替えしきい値を変える

```text
--tab-strip-height-transition-threshold=2000
```

これは、タブバーの高さを2000にする指定ではない。

Chromiumのソースでは、タブバーの高さの切り替えに関するしきい値をDP単位で上書きするオプションとして定義されている。

今回の環境では、これを後述の端末状態の切り替えと組み合わせることで、内側全画面のタブバーを非表示にできた。

せっかくの大画面だ。

文字は読みやすくしたいし、表示領域も広く使いたい。

注文が多いとは思う。

しかし、こちらも折りたたみスマートフォンを買っているのである。

## 第7章：なぜか、一度外へ出ないと帰ってこられない

そして、今回いちばん大事なのが、この部分だ。

```bash
~/rish -c 'cmd device_state state 0'
~/rish -c 'am start -W -n com.android.chrome/com.google.android.apps.chrome.Main'
~/rish -c 'cmd device_state state reset'
```

私の環境では、端末状態を一時的に切り替えて外画面側へ移し、Chromeを起動してから、状態の上書きを解除して元へ戻している。

**画面をいったん外へ飛ばして、戻す。**

Chromeを快適に使いたいだけなのに、外出と帰宅が必要になった。

ここでの `reset` は端末の初期化ではない。`device_state` で指定した状態の上書きを解除する操作である。

また、`am start -W` は起動を待ってから次へ進む指定だ。ただし、ページの読み込みや描画がすべて完了するまで待つ、という意味ではない。

### これは省略しない方がよい

検証では、`device_state` の切り替えを省略すると、タブバーが復活した。

つまり、少なくとも今回の端末では、起動オプションを書くだけでは足りなかった。

<font color="#ba711d"><strong>この「外画面へ移してから戻す」操作が使えない環境では、おそらく同じようには動かない。特に、内側画面でのタブバー非表示を再現できない可能性がある。</strong></font>

User-Agent指定だけの効果とは、分けて考える必要がある。

なお、`state 0` をすべてのFoldで共通の「外画面コマンド」だとは考えないでほしい。端末状態のIDや利用できる操作は機種・OSによって異なるため、別の環境へそのまま適用できるとは限らない。

なぜこの順番でうまくいくのか。

起動時の画面状態がChromeのタブバー表示に影響しているのではないか、と考えている。ただし、内部の処理経路まで特定できたわけではない。

わかっているのは、省くと戻ってきた、ということだ。

タブバーには律儀なところがある。

### 途中で止まった場合

成功したスクリプトは単純な順次実行で、エラー時の自動復旧処理までは入っていない。

状態を切り替えたあとに中断し、画面の状態が戻らない場合は、rishを使える状態で上書きを解除する。

```bash
~/rish -c 'cmd device_state state reset'
```

うまく動かないときは、先にShizukuとrishが動いているか、各コマンドでエラーが出ていないかを確認する。

## 第8章：警告を消したら、自動化まで始まっては困る

もうひとつ、今回使っているオプションがある。

```text
--enable-test-intents
```

検証では、これを加えると「Chromeがコマンドラインファイルからフラグを読み込んでいます」という警告が表示されなくなった。

ただし、これは名前のとおりテスト用Intentの処理を有効にするためのオプションである。

警告非表示のための正式な設定として案内されているものではない。今回は、その副次的な挙動を実機で確認して使っている。

また、最終版には `--enable-automation` を入れていない。

検証時のSannySoftでは、`navigator.webdriver` の値は `false` だった。ただし、プロパティ自体は存在し、プラグイン関連では失敗の表示もあった。

これは検査時点の結果であって、すべてのサイトのボット判定を通過するという話ではない。

私はニュースを読みたいのであって、Chromeに何かの潜入任務を頼んでいるわけではない。

## 第9章：帰り道も用意しておく

気に入って使っているとはいえ、元へ戻せることは大事だ。

こちらを `chrome-stock.sh` として保存する。

```bash
#!/data/data/com.termux/files/usr/bin/bash
~/rish -c 'am force-stop com.android.chrome'
~/rish -c 'rm -f /data/local/tmp/chrome-command-line'
~/rish -c 'am start -W -n com.android.chrome/com.google.android.apps.chrome.Main'
```

起動オプションのファイルを削除して、Chromeを起動し直す。

```bash
bash chrome-stock.sh
```

ただし、<font color="#467cc7"><strong>このスクリプトだけではデバッグアプリ指定は解除されない。</strong></font>

今回の設定を片付ける場合は、追加で解除する。

```bash
~/rish -c 'am clear-debug-app'
```

状態の上書きが残っている場合は、前章の `device_state state reset` も実行する。

以前の試行で `TOAST_WINDOW` を `ignore` に変更していた場合だけ、こちらも戻す。最初から変更していなければ不要だ。

```bash
~/rish -c 'cmd appops set com.android.chrome TOAST_WINDOW allow'
```

ちなみに、タブバーだけ消して、User-Agentは変えたくない場合は、設定ファイルへ書き込む内容を次の形にする。外画面を経由する手順などは同じだ。

```text
chrome --enable-test-intents --tab-strip-height-transition-threshold=2000
```

### アップデート後は、また確認する

Chromeの `chrome://version` では、実際に反映されたコマンドラインを確認できる。

更新後は、オプションの反映、タブバーの有無、普段読むサイトの表示をそれぞれ確認する。固定したUser-Agentのバージョンも見直す。

起動オプションは、変更・廃止されることがある。これはChromiumの公式ドキュメントにも明記されている。

今回の方法も、万人向けの完成された設定ではない。

<font color="#467cc7"><strong>自分の端末で、自分の読みたいサイトを、自分の目に合わせるための調整である。</strong></font>

## 最終章：それでも、私はPixel Foldを使い倒す

ここまで読んで、こう思う人もいるだろう。

「そこまでしなくても、別のブラウザを使えばいいのでは？」

検討する価値はある。

ただ、私は今のところ、この使い方が気に入っている。

前回は、故障しても使い続ける話だった。

今回は、使いにくいところを調整して使い続ける話である。

大画面を開いて、読みたい記事を、自分の読みやすい形で読む。

そのために、タブバーを消し、User-Agentを指定し、必要なら一度外画面へ飛ばして戻す。

手間はかかる。

しかし、好きな道具を、自分の道具にしていくのは楽しい。

私はPixel Foldが好きだ。

大画面が好きだ。

だから、多少の不便は自分で何とかする。

ただ、Googleさん。

**大きな画面を買ったのに、小さな文字を読まされるのは、そろそろ勘弁していただきたい。**

それから、せっかく増えた表示領域まで、小さなタブで埋めないでいただけると助かります。

ちなみに、このスクリプトを使い始めて約1年。

私のChromeは少しずつ快適になっている。

一方、私の目は少しずつ悪くなっている。

どうやら、こちらの開発速度の方が追いついていないらしい。
